- Дизайн и CSS не менялись. Версия URL `home-dashboard.js` увеличена для обновления кеша. Предупреждение о сохранении появляется только при ошибке.

## Проверки

Выполнены **22 сценария в настоящем Chromium**. Для каждого проверено отсутствие необработанных ошибок JavaScript.

2. Тот же цикл при мобильном viewport 390×844 с touch/mobile emulation. Проверено отсутствие горизонтального переполнения главной.
3–6. Удаление исходных товаров в косметике, электронике, одежде и «Ногти» с перезагрузкой, включая тушь и машинку.
7. Старые ID удалений и переименование ночнушки.
8. Приоритет современной отметки `false` над старой `true`.
9. Чтение старой отметки после изменения категории.
10. Сохранность исходных значений всех тестовых ключей при загрузке, включая одежду, «Ногти», заметки, план и чешский словарь. Миграция записей из устаревших категорий без удаления исходных данных.
11. Приоритет сохранённой категории над классификацией по названию и отсутствие дублей.
12. Возврат исторически купленного средства в активную косметику.
13. Удаление ингредиента и явное повторное добавление из рецепта.
14–17. Неподдерживаемые данные: `null`, сломанный JSON, число, строка. Главная работает; исходные значения не перезаписываются даже при попытке записи.
18. Смешанные повреждённые и корректные записи заметок/плана.

## Структура и пределы проверки

Проект состоит из `index.html`, `home-dashboard.js` и `home-dashboard.css`. Основной скрипт содержит данные, обработчики, миграции и рендеринг. Dashboard использует его глобальные данные и заменяет `renderToday`. Пять обработчиков рецептов частично дублируются; сортировка категорий выполняется отдельным MutationObserver. Полный рефакторинг не делался: он не нужен для этих исправлений и увеличил бы риск.

В исходном интерфейсе **нет отдельного редактора названий покупок и кнопки переноса между категориями**. Добавление, удаление и покупка проверены через интерфейс. Перенос проверен через добавленную функцию `moveShoppingItem`, без изменения интерфейса. Редактирование заметок/дневного плана сохранено, некорректные записи защищены при рендеринге.

У старого customItems нет истории выбора категории: невозможно надёжно отличить ошибочную старую запись в «Дом» от осознанного выбора пользователя. Поэтому современные сохранённые категории не переопределяются по ключевым словам. Исходные и устаревшие списки классифицируются исправленными правилами.

Реальные данные localStorage телефона недоступны из локальной копии проекта. Проверки выполнены на тестовых наборах старого и текущего формата. Уже стёртые прежним кодом данные автоматически восстановить невозможно. Повреждённый ключ остаётся неизменным и требует отдельного восстановления; изменения в него не считаются надёжно сохранёнными, отображается предупреждение.

Обновление опубликованного сайта не выполнено: для него требуется разрешённый пользователем push.
